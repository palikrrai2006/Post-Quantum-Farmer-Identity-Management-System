SourceAFIS Matcher

SourceAFIS is an Automated Fingerprint Identification System (AFIS) that extracts biometric minutiae points (ridge endings and bifurcations) from fingerprint scans. It generates a standard template used for biometric comparisons.

  • Function: Template generation & fast matching
  • Security focus: No raw fingerprint images stored

AES-256-GCM

Advanced Encryption Standard (AES) with a 256-bit key operating in Galois/Counter Mode (GCM). This provides both symmetric confidentiality and authenticated integrity verification (AEAD) for the stored fingerprint template.

  • Function: Authenticated data encryption
  • Security focus: Protection of biometric template at rest

ML-KEM-1024

ML-KEM (Module-Lattice-Based Key Encapsulation Mechanism) is a post-quantum cryptographic algorithm standardized by NIST (FIPS 203). It is designed to exchange symmetric session keys in a way that is secure against quantum computer attacks.

  • Strength: Equivalent to AES-256 security
  • Security focus: Quantum-resistant key exchange

ML-DSA-87

ML-DSA (Module-Lattice-Based Digital Signature Algorithm) is a lattice-based signature scheme standardized by NIST (FIPS 204). It provides mathematical proof of authenticity and integrity for each enrolled digital identity.

  • Strength: Highest NIST security level (Category 5)
  • Security focus: Post-quantum identity authentication

SHA3-256 Hash

Keccak-based Secure Hash Algorithm (SHA-3) is the latest hashing standard by NIST. It computes a fixed-size cryptographic digest of the encrypted package to seal data integrity before committing it to storage.

  • Function: Cryptographic integrity verification
  • Security focus: Detects unauthorized data alterations

IPFS + Blockchain

A decentralized storage strategy. Encrypted packages containing the signed templates are stored on InterPlanetary File System (IPFS) to obtain a Content Identifier (CID). The CID and SHA-3 hash are then anchored on the Ethereum blockchain.

  • Function: Decentralized data anchoring
  • Security focus: Avoids single point of failure (SPOF)

Note for Examiners

This implementation integrates real bindings to liboqs for ML-KEM and ML-DSA, running in a native Python backend environment. The matching engine relies on a JVM-bridged SourceAFIS instance. No cryptographic simulation is used.
